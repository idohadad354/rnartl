Security Policy

Effective October 22, 2026

Architecture

  • RNA RTL is a static user interface hosted and served by Atlassian Forge. It has no backend functions, servers, database, credentials or API keys.
  • It requests no Atlassian OAuth scopes. It reads only the macro it is rendering, which Confluence passes to it directly.
  • It runs in Forge's sandboxed iframes under Atlassian's Content Security Policy. The only extra permissions are inline styles (for text colors) and loading images from addresses that authors insert.
  • Content is stored by Confluence, so it inherits Atlassian's encryption, backups and data residency.

Secure development

  • Dependencies are pinned with a lockfile, and every release is blocked automatically if npm audit reports a high or critical vulnerability in shipped code.
  • Every release passes an automated test suite, including validation of all saved content against Atlassian's official document schema.
  • Link and image addresses are sanitized: javascript:, data: and similar schemes are rejected.
  • Developer and Marketplace accounts are protected with two-step verification, and only the vendor can deploy releases.

Reporting a vulnerability

Email hadadapps@gmail.com with the details and steps to reproduce. We acknowledge reports within 2 business days, keep you informed, and fix confirmed issues within the timeframes of Atlassian's Marketplace security bug fix policy. Please give us a reasonable chance to fix an issue before disclosing it publicly.

Incident response plan

  1. Triage. Confirm the report, rate severity with CVSS, and record a timeline.
  2. Contain. Ship a fix or a safe rollback through Forge, which updates every installation without customer action.
  3. Notify. Inform Atlassian within 48 hours of becoming aware of a security incident, and affected customers without undue delay (within 72 hours where personal data is affected).
  4. Recover and review. Verify the fix, then write a post-incident review with root cause and preventive actions.
